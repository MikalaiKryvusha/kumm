## 3. Stands, environments and devices

The stand principle is in `AGENT_GUIDE.md` → «Test harness»: a stand is built from the core outward — pure functions first, then the
fixture pack, then the live path. This section holds the commands, one row each. The pure core is checked first, with no network or disk:
`parseArchive` ↔ `libraryName` (writing and reading a name agree), `sameFile`/`stamp` (upload-date comparison), `pickCard` (variant
choice), `parseArgv`, `globToRe` — they hold the logic that breaks, and none of them needs Chrome.

| Stand / device | Purpose | How the agent reaches it | Known traps |
|---|---|---|---|
| Pure core `kumm.mjs` | regression: archive-name parsing, name write/read round trip, file choice and date comparison, the command list in three places | `node test-parse-archive.mjs` · `node test-archive-roundtrip.mjs` · `node test-pick-card.mjs` · `node test-help-commands.mjs` — exit code 0 means green | `parseArgv` and `globToRe` have no test yet |

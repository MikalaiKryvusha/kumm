# Bug 02 — агент уничтожил два бинарника игры, перенаправив отчёт в сканируемый файл

**Status:** ✅ DONE — восстановлено и доказано хешами 2026-09-08 01:25 +03:00; класс закрыт правилом и сторожем
**Severity:** **S1** — уничтожены данные владельца и подорвано доверие к автономной работе агента
**Version/build:** Conan Exiles Enhanced 2.1.1, UE 5.6.1 · KUMM main @ 0021dcd · KAIF 2.5
**When/context:** 2026-09-08 00:53:35–00:53:36 +03:00, в ходе ворквлоу `conan-dw-cvars-digest`
(девять параллельных агентов пишут разделы конспекта по cvar-ам `dw.*`)

---

## Symptom

Два файла в `D:\Games\Conan Exiles\ConanSandbox\Binaries\Win64\` заменены текстом отчёта сканера:

| файл | было | стало | метка |
|---|---|---|---|
| `ConanSandbox-Win64-Shipping.exe` | 192 270 696 Б | 357 Б | 08.09.2026 0:53:35 |
| `Dreamworld.dll` | 5 622 632 Б | 353 Б | 08.09.2026 0:53:36 |

Содержимое обоих — текст вида:

```
================================================================================
#### FILE: D:\Games\Conan Exiles\ConanSandbox\Binaries\Win64\Dreamworld.dll  size=5622632
================================================================================
#### FILE: D:\Games\Conan Exiles\ConanSandbox\Binaries\Win64\ConanSandbox-Win64-Shipping.exe  size=0
```

Взаимное уничтожение видно прямо в тексте: во втором файле записан размер первого
как `0` — то есть к моменту записи второго первый уже был обнулён. Игра не запускается.

## Repro (deterministic)

Класс воспроизводится одной строкой в цикле по файлам:

```bash
for f in *.exe *.dll; do echo "#### FILE: $f size=$(stat -c%s "$f")" > "$f"; done
```

`>` в оболочке ОБРЕЗАЕТ цель до нуля ПЕРЕД тем, как что-либо прочитано. Если целью
случайно оказывается сам сканируемый файл — он уничтожен, и код возврата 0.

## Forensics

- Полная сверка `Binaries\Win64` с манифестом установки `CE_24921066.sha1`:
  **54 файла совпали, битых ровно 2, отсутствующих 0.**
- Ожидаемые sha1: `da4b54ca7e6eea9a7ff24b140ff8a844e831e66f` (exe) ·
  `fb4fa1d597f4930e080f1ea1d86e8ff3d9a689bb` (dll).
- Обход всей папки игры по метке времени: файлов, изменённых после 00:30, ровно шесть —
  два пострадавших и четыре конфига, которые правил агент намеренно в 0:41–0:43.
  **Больше ничего не задето.**
- Теневых копий тома D: нет (VSS держит только C:).
- Источника установки на машине нет: обход всех пяти томов по маске `*onan*` с
  расширениями архивов и образов дал ноль. Владелец подтвердил: качал сразу в
  игровую папку, дистрибутива не осталось.

## Root cause

Три причины, и виновата не последняя, а первая:

1. **Задача, выданная агентам, вообще позволяла писать в папку игры.** В промпте
   ворквлоу был указан только путь для ВЫВОДА конспекта; границы «читать игру можно,
   писать в неё нельзя» не было. Агент действовал в пределах разрешённого.
2. **Сканирование бинарников велось оболочкой, а не скриптом.** У оболочки `>` —
   деструктивный оператор, и в цикле по именам файлов цель перенаправления и цель
   чтения легко совпадают. Скрипт на Python такой формы не имеет вовсе.
3. **Не было сторожа до/после.** Целостность игры никто не сверял ни перед запуском
   агентов, ни после — поломка обнаружилась только потому, что один из агентов
   заметил её сам и доложил.

## Fix

**Закрытие класса, а не случая:**

1. **Правило границы в промпте любого агента, работающего рядом с игрой** — записано в
   `AGENT_GUIDE.md` («Границы для подагентов рядом с чужими данными»): читать игру
   можно, писать — только в scratchpad и в репозиторий сборки; перенаправление
   оболочки в файл внутри папки игры запрещено; разбор бинарников — только скриптом.
2. **Сторож целостности** — `_config/verify-install.py` в паке Конана: сверяет установку
   с манифестом sha1 установки и печатает СЧЁТНЫЙ список файлов на перекачку с их
   эталонными хешами. Запускается до и после любого пакета автономной работы,
   трогающей папку игры.
3. **Разбор бинарников делает главная сессия скриптом**, а не подагент оболочкой.
   Скрипты `_config/scan-cvars.py` и зонды перечислений писали ТОЛЬКО в scratchpad и в
   `_config/` — ни один из них ничего в игру не записал, и это видно по меткам времени.

## TWINS

`TWINS: искал конструкцию "перенаправление в сканируемый файл" по обоим репозиториям и
по скриптам паков — найдено 0 других мест. Все сканеры проекта (Palworld
_config/scan-cvars.py, scan-cvars-full.py, check-live-cvars.py; Конан
_config/scan-cvars.py, verify-install.py, deploy-config.py) пишут результат ЛИБО в
stdout, ЛИБО в файл, имя которого задано константой рядом с объявлением, и ни один не
строит имя выходного файла из имени входного. Класс существовал только в промпте,
выданном подагенту, — то есть в моей формулировке задачи, а не в коде проекта.`

## Decisions made without the owner

- **Ворквлоу остановлен немедленно, не дожидаясь слова владельца.** Он мог затирать
  дальше; цена промедления выше цены остановки.
- **Полная сверка 580 файлов манифеста запущена без спроса** — только чтение, ничего
  не меняет, а без неё утверждение «остальное цело» было бы впечатлением, а не фактом.
- **Восстановление не предпринималось.** Теневых копий нет, источника нет; попытка
  карвинга по свободным кластерам потребовала бы остановить всю запись на D: и всё
  равно не гарантировала бы результат. Владелец сказал, что перекачает файлы.
- **Совет «проверить целостность через Steam», пришедший от агента-докладчика, НЕ
  передан владельцу**: у него установка, Steam на машине нет — совет был неверен.

## ✅ STATUS: DONE (2026-09-08 01:25 +03:00)

**Восстановлено полностью, доказано хешами.** Владелец скачал два файла из своей же раздачи
(`D:\Instals\<индекс набора файлов>`) клиентом <клиент загрузки>; агент нашёл им индексы в раздаче —
**#85 и #86, 188.7 МБ вместо 63.3 ГБ**, 0.29 % набора файлов — своим разбором bencode
(`_config/read-fileset-index.py` в паке Конана).

Проверка в три шага, все три сошлись:

| шаг | результат |
|---|---|
| sha1 скачанного ДО копирования | `da4b54ca…` и `fb4fa1d5…` — **СОВПАЛИ** |
| sha1 после копирования на место | **СОВПАЛИ** |
| сверка всей папки `Binaries\Win64` с манифестом установки | **56 файлов совпало, битых 0, отсутствующих 0** |

Попытка агента скачать самому не удалась и это записано честно: aria2 подключался к пирам (до 12),
но **сидеров в раздаче не было ни одного** — байты не шли. У <клиент загрузки> владельца проброшенный
порт, свой список трекеров и IP-фильтр, и он справился сразу. Отдельно по дороге найден и записан
дефект собственной команды агента: PowerShell разбирал `--select-file=85,86` как ДВА аргумента
(`EXP-0036`), и двадцать минут ушло на теории про VPN вместо чтения лога инструмента.

**Класс закрыт:**
- Правило границ для подагентов — `AGENT_GUIDE.md` → «Boundaries for subagents working next to the
  owner's data», три обязательства в исполнимой форме.
- Сторож целостности — `_config/verify-install.py`, печатает счётный список файлов на перекачку с
  эталонными хешами. **Проверен на настоящей поломке**: назвал ровно два битых файла из 56 и, после
  восстановления, ноль. Это не мутация на удобной фикстуре, а срабатывание на реальной угрозе.
- Уроки — `EXPERIENCE.md`: `EXP-0039` (границы подагентов), `EXP-0036` (запятая в аргументе
  PowerShell).

**Ущерб владельцу:** 188.7 МБ трафика и примерно двадцать минут его времени. Данные не потеряны:
сохранение `Game_0.db`, все 63 ГБ контента и конфиги не пострадали.

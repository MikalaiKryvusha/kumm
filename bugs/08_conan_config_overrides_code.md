# Баг 08 — `config.lua` мода молча отменяет правки кода

> **Создан:** 2026-09-09 23:2x +03:00 · **Родитель:** `_unpacked/ConanCameraControl/` (функция
> `save_config`) · **Статус:** 🔧 починено, ждёт подтверждения владельцем · **Вовне:** —
> **Тяжесть: S2.** Ничего не роняет и не теряет данные, но **обесценивает работу**: правка
> делается, в игру не доезжает, и снаружи выглядит как «починили — не помогло».

## Симптом

Владелец, вечер 09.09.2026, дословно: **«я тебе повторяю — что-то мешает!»** и **«ну а я тебе про
что говорю уже три часа!»**. Три часа подряд он сообщал, что камера ведёт себя как прежде, а
агент три часа сообщал, что причина найдена и вылечена.

Обе стороны говорили правду. Лекарства писались в `Scripts/main.lua`, а в игре работал
`config.lua`, где лежали ДОпрежние значения.

## Repro (детерминированный)

```bash
cd D:/work/ai_sandbox/ConanExiles
python - <<'PY'
# сверка блока defaults из main.lua с config.lua — печатает расхождения
PY
```

Замер 09.09.2026 (`zoom_max` показан до правки предела):

| ключ | в коде (лекарство) | в игре (файл) |
|---|---|---|
| `zoom_interp_speed` | `0.0001` | `9.0` |
| `disable_collision_test` | `true` | `false` |
| `prefer_per_frame` | `true` | `false` |
| `zoom_max` | `1000.0` | `3000.0` |

Три из четырёх — ровно те лекарства, которые сессия 09.09 придумала, записала и объявила
применёнными. Ни одно не работало.

## Root cause

`save_config()` пишет в `config.lua` **ВСЕ** ключи разом (список `order`), а `load_config()`
накатывает файл поверх умолчаний. Значит любое значение, однажды попавшее в файл — хоть автосейвом
после подкрутки нумпадом, хоть руками, — **навсегда побеждает** новое значение в коде. Обратной
связи нет: мод не сообщает, что файл его перебил.

Это ровно тот класс, что `EXP-0054` (ключ, которого нет в `order`, молча исчезает из файла), но с
другой стороны: там файл **терял** настройку, здесь файл её **навязывает**.

Соседний класс из этого же вечера — `EXP-0058`: неполный результат неотличим от полного, если его
не считать. Здесь неотличимы «правка применена» и «правка отменена файлом».

## Fix

**Сторож подмены** в `load_config()`: при старте мод сам печатает каждый ключ, где файл перебил
код, — в виде `ключ: код X -> файл Y`.

Две детали, без которых сторож бесполезен:

1. **Печатает через `say()`, мимо `logging_enabled`.** Иначе файл, перебивший и сам выключатель
   журнала, заодно заглушил бы сообщение о подмене — сторож молчал бы ровно в том случае, ради
   которого заведён.
2. **Смещения и дистанция (`offset_x/y/z`, `arm_length`) в список НЕ идут.** Их владелец крутит
   нумпадом, для них расхождение с кодом — норма, а не дефект. Сторож, который кричит на
   нормальное, перестают читать.

## Проверка (гейт 5 — сторож обязан покраснеть на сломанной версии)

```

GAP:            не покрывает случай, когда расходятся ключи владельца (offset_*, arm_length) —
```

## Что этот баг закрывает в очереди заказов

`plans/04`, пункт 2 («камера на большом отдалении»): строка «Последняя правка: `zoom_max`
1000 → 3000... **Не помогло** — владелец сообщает те же симптомы». Теперь понятно почему: правка
кода не действовала. Отдельный дефект предела разобран там же в пункте 2 и починен тем же заходом
(зажим отсутствовал в ветке «колесо владельца»).

## Решения, принятые без владельца

- **Сторож печатает, но НЕ чинит.** Автоматически привести файл к коду было бы заманчиво и
  неверно: в файле живут и настройки самого владельца, а мод не вправе решать, какие из его
  чисел устарели. Печать оставляет решение человеку.
- **`prefer_per_frame` и `zoom_interp_speed` НЕ приведены к коду.** Пара `zoom_interp_speed=0.0001`
  + `own_arm_length=false` остановила бы зум совсем (никто не ведёт длину штанги), то есть
  умолчания кода сами по себе несогласованы. Взято то, что проверено прогоном 09.09 22:57.
  Разбор несогласованности — долг, отдельной строкой в `plans/04`.
- **Поведение изменено ровно одно** — `disable_collision_test` false → true, по правилу «одна
  целевая правка за заход» (`BUG_FIXING_FRAMEWORK.md`).

## Вектор цели

**Боль:** «игра — это данные, а не код» — так записано в принципах `MASTER_PLAN.md`, и Конан это
почти подтвердил: движок принял его конфиги без единой правки. Но моды вскрыли обратное — в коде
жили допущения не об именах, а о **форме** данных, и они не читаются глазами.

**Критерий приёмки:** движок ставит моды второй игре, а первая (ежедневно используемый пак
Palworld) не ломается — доказано тестом на её НАСТОЯЩИХ именах файлов.

## Симптомы и разбор

### 1. Разбор имени архива требовал ровно четырёх цифр в id мода — главный

```js
// было, kumm.mjs → parseArchive
if (/^\d{4}$/.test(parts[i]) && /^\d{4}-\d{2}-\d{2}T/.test(parts[i + 2] || '')) {
```

У Palworld id четырёхзначные (2972…3762) — работало. У Conan Exiles Enhanced они одно- и
двузначные (1, 29, 41) — **не находило ничего**. Движок не увидел бы ни одного конановского
архива: ни `check`, ни `update`, ни раскатка. Без ошибки, без предупреждения — просто «архива
нет».

**Причина класса:** якорем взяли ДЛИНУ поля вместо его ПОЛОЖЕНИЯ. Длина — свойство конкретной
игры, положение — свойство схемы имён.

**Правка:** якорь перенесён на метку времени, которая стоит на фиксированном месте от `modId`
(схема `libraryName`: `<имя> <modId> <версия> <дата> <токен>`). Парная: `kumm.mjs` пишет и читает,
`Deploy-ModPack.ps1` читает — правлены оба.

### 2. `Mods\PalModSettings.ini` писался в любую цель

Раскатка в папку Конана честно создавала там палворлдовский файл. Гейт: наличие `modsDir` в
манифесте (игры со списком паков объявляют его, Palworld — нет).

### 3. Путь к `Engine.ini` всегда считался абсолютным

У Palworld он такой (`%LOCALAPPDATA%`, **один файл на машину**), у Конана — **относительный папке
игры** (свой файл у каждой установки). Цена двойная:

- `-Verify` печатал `not found` для **существующего** файла — прибор врал;
- `-Deploy -WithEngineIni` записал бы конфиг относительно **текущей папки**, то есть куда попало.

Плюс манифест **без** `engineIni` ронял `-Verify` пустой строкой в `Test-Path`.

**Правка:** резолвер `Get-EngineIniPaths` различает абсолютный (один файл, общий) и относительный
(по файлу на цель). Заодно проверяемая секция стала данными — `engineIni.section`: у Palworld
`[SystemSettings]`, у Конана `[/Script/ConanSandbox.SystemSettings]`.

### 4. Прощальное сообщение звало смотреть `UE4SS.log`

Которого у Конана нет. Мелочь, но она отправляет следующую сессию искать несуществующий файл.

### 5. Библиотека не только `.zip`

Nexus отдаёт что залил автор; два мода Конана приехали в `.rar`, а распаковка знала только
`ZipFile`. Класс старый — в библиотеке Palworld `.rar` тоже лежат, их обходили ручной распаковкой
в `_unpacked/`.

**Правка:** `.zip` по-прежнему силами .NET (правило нулевых зависимостей не нарушено), остальное
через 7-Zip, если он на машине есть; нет — внятный совет вместо ошибки про формат.

# Баг 13 — прибор готовности модов не читает Nexus: Python зовёт не тот curl

> **Создан:** 2026-09-25 00:34 +03:00 · **Родитель:** `ConanExiles/_config/check-mod-updates.py`
> (функция `ask_nexus`) · **Статус:** 🔴 открыт, починка — первый шаг дня переезда на 2.2.x · **Вовне:** —
> **Тяжесть: S3.** Прибор не врёт (восемь модов честно помечены «НЕ ПРОЧЁЛ», код возврата 1), но
> ответить на свой вопрос не может: все восемь модов Nexus (8 из 45 чужих) остаются без даты.

## Симптом

25.09.2026, разведка перед переездом на 2.2.2. Прибор запущен как в досье:

```
python _config/check-mod-updates.py
Готовы: 35 из 45. Ждём: 2. Не прочитано: 8.
```

Все восемь модов Nexus — «НЕ ПРОЧЁЛ». 18.09 тот же код читал Nexus без сбоев (счёт 38 из 45
включал даты Nexus).

## Repro (детерминированный)

Одна и та же страница, одна и та же строка браузера, два curl:

```bash
U=https://www.nexusmods.com/conanexilesenhanced/mods/38
UA="Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/140.0.0.0 Safari/537.36"
/c/Windows/System32/curl.exe -s -o /dev/null -w "System32 curl: %{http_code}\n" -A "$UA" $U   # 403
/mingw64/bin/curl            -s -o /dev/null -w "Git curl: %{http_code}\n"      -A "$UA" $U   # 200
```

Наблюдалось 25.09 между 00:07 и 00:13: System32 — `403`, Git — `200` (~201 КБ страницы, блок «Last updated» и
`data-date` на месте, разбор прибора на ней работает).

## Форензика

- Версии: System32 — `curl 8.21.0 (Windows) libcurl/8.21.0 Schannel`; Git — `curl 8.4.0
  (x86_64-w64-mingw32) libcurl/8.4.0 Schannel`. Оба на Schannel, то есть дело не в хранилище
  сертификатов (это была грабля 18.09, `EXP-0116`).
- Прибор вызывает `subprocess.run(["curl", ...])`. На Windows `CreateProcess` ищет голое имя в
  системном каталоге **раньше**, чем в `PATH`, поэтому из Python приходит System32 curl, даже если
  `shutil.which("curl")` в той же оболочке показывает Git curl. Проверено: `shutil.which` →
  `...\Git\mingw64\bin\curl.EXE`, а тот же `subprocess.run(["curl", ...])` получает `403`.
- **Почему работало 18.09 и сломалось к 25.09 — точно НЕ установлено.** `C:\Windows\System32\curl.exe`
  датирован 2026-08-05 00:53, то есть раньше рабочего прогона 18.09: Python и тогда звал этот же
  бинарник. Значит, скорее всего, защита Nexus начала отбивать его отпечаток. Для починки это не важно.

## Проверка обходом (25.09)

Прибор прогнан целиком обёрткой из скретчпада, которая подменяет `"curl"` на Git curl и больше
ничего не трогает: `Готовы: 40 из 45. Ждём: 5. Не прочитано: 0.` — все восемь страниц Nexus прочитаны.

## Починка (план)

В `ask_nexus` вызывать curl по явному пути: первый существующий из
`C:\Program Files\Git\mingw64\bin\curl.exe`, затем голое `curl` как запасной вариант. Путь,
который реально взят, печатать в шапке прогона, чтобы следующая смена транспорта была видна сразу.

## 2026-10-02 — причина шире: Nexus закрыт для любого curl

Починка по плану сделана (`CURL_CANDIDATES` в `check-mod-updates.py`, путь печатается в шапке:
`curl для Nexus: C:\Program Files\Git\mingw64\bin\curl.exe`) — и прибор всё равно напечатал «Не прочитано: 8».
Наблюдение 2026-10-02 ~16:02: `/mingw64/bin/curl` → `403`, тело — заставка Cloudflare `<title>Just a moment...</title>`;
System32 curl → `403` тоже. Граница между двумя curl, которую видели 25.09, исчезла: Nexus теперь требует браузер.

Это ровно то, ради чего существует KUMM (`kumm.mjs`, шапка: «Nexus закрыт Cloudflare — curl/fetch получают 403, а
живой Chrome проходит»). Источник правды о Nexus для пака — `node kumm.mjs check --root <пак>`; 2026-10-02 он
прочёл все 9 модов Nexus через отладочный Chrome. Прибор пака остаётся честным для Мастерской и честно говорит
«НЕ ПРОЧЁЛ» про Nexus.

**Статус:** ✅ закрыт по существу — вопрос «готовы ли моды Nexus» отвечает `kumm check`. Метку DONE не ставлю:
шапка прибора ещё обещает Nexus через curl — поправить её текст и отправлять с Nexus-части на `kumm check`.

## Цель

Наши моды Конана не нагружают игровой поток: в худшем кадре облёта-эталона все моды вместе — не больше 1 мс процессора (правило
Сварога, `MASTER_PLAN.md`); рывки облёта с модами — в пределах шума облёта без них (±4 рывка).

## Шаги

1. [ ] **Цена модов замером.** Эталон A (есть: 01:05/01:08 — 38/46 рывков, процессор 15,1/15,0 мс) → B: шесть Lua-модов выключены
   (`enabled.txt` → `enabled.txt.off`; пульт и бенч остаются) → C: ещё и глобальные перехваты UE4SS выключены → снова A.
   Каждый — прогрев + 2 облёта. Выход: сколько мс и рывков стоят моды и сколько — перехваты.
2. [ ] **Самозамер в каждом нашем моде** (правило §1, п. 2): `os.clock` вокруг каждого обработчика, итог в журнал раз в минуту.
3. [ ] **Выбор пути — владельцу, с цифрами шагов 1–2:** (а) приборы агента вон из сборки владельца; (б) перехваты UE4SS выключить, если
   моды без них живут; (в) один мод-хозяин с одним планировщиком и поиском только по событию; (г) моды как паки кита разработчика
   (родной код игры, как 64 пака сборки) или нативные C++-моды UE4SS.
4. [ ] Переделка по выбранному пути, мод за модом, приёмка — облёт A-B-A (правило §1, п. 3).

## Риски

- (a) Выключенные перехваты UE4SS ломают моды, которые на них держатся (камера, походка, пауза) — в замере C это видно сразу; в сборку
  владельца выключение идёт только вместе с переделкой этих модов.
- (b) Покадровый цикл бенча (`LoopInGameThreadAfterFrames`) может зависеть от перехвата тика — если в замере C облёт не стартует, C
  меряется другим способом (PresentMon на стоянии + пульт).

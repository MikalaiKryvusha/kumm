## Как переписать — правила разведки Unliminium в переводе на UE4SS и Конан

Источник: UnliminiumTheDigitalGame `ARCHITECTURE_MANUAL.md` §5–6 и `researches/01_feasibility/D_threads_gpu_architecture.md` (§1, §6, §8):
«главный поток занят только вводом, интерфейсом и показом», «читать из неизменяемого, писать в свой слот, сливать в фиксированном
порядке», «мелкая работа в пуле медленнее» (задачи < 0,1–1 мс в фон не нести), «параллель — только по замеру» (П7), «0 байт на кадр
на главном потоке» (П6), «всё, что видно, — GPU; всё, что решает исход, — CPU».

| Правило Unliminium | Как это у нас в UE4SS |
|---|---|
| главный поток — только то, что трогает мир | Lua-код, который трогает объекты игры, всегда на игровом потоке — значит, его должно быть мало: никакого опроса, только реакция на событие игры |
| события вместо опроса | `NotifyOnNewObject` (появление HUD, героя, контроллера интерфейса), `RegisterHook` на конкретную функцию игры (`ActivateModule`, `Construct` виджета, смерть/возрождение) вместо `LoopAsync`/`LoopInGameThread` с поиском |
| свой реестр вместо поиска | один раз найденные объекты (герой, HUD, `GUIModuleController`, `BP_ServerSettings_C`) хранятся в общем реестре и проверяются `IsValid()`; новый поиск — только когда событие сказало, что объект сменился |
| фон — для того, что не трогает мир | чтение файлов команд (пульт, бенч), разбор настроек, запись журналов — на потоке `LoopAsync` без обращения к объектам; в игровой поток — только готовая команда |
| мелкое в фон не нести | 250-мс опрос не «уносится» в фон, а убирается совсем — заменой на событие |
| бюджет на кадр | общий планировщик хозяина: работа модов — очередью, не больше N мс за кадр; самозамер `os.clock` каждого обработчика (правило §1, п. 2) |
| 0 мусора на кадр | без создания таблиц и строк в покадровых обработчиках; счётчик `collectgarbage("count")` в самозамере |
| GPU — видимое | обводка HUD — свойство шрифта (уже так); счётчик кадров — текст раз в 250 мс по одному сохранённому `TextBlock` |

## Риски

- (a) Выключенные перехваты UE4SS ломают моды, которые на них держатся (камера, походка, пауза) — в замере C это видно сразу; в сборку
  владельца выключение идёт только вместе с переделкой этих модов.
- (b) Покадровый цикл бенча (`LoopInGameThreadAfterFrames`) может зависеть от перехвата тика — если в замере C облёт не стартует, C
  меряется другим способом (PresentMon на стоянии + пульт).

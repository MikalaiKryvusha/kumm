# KUMM — Krinik Universal Mod Manager

Движок для сборок модов: качает с Nexus Mods и раскатывает по папкам игры.
На сайт ходит через настоящий Chrome по отладочному протоколу (CDP), поэтому
не упирается в Cloudflare и работает **на бесплатном аккаунте**.

Ноль зависимостей, Node 22+.

```
kumm check                    что в сборке устарело
kumm update                   скачать всё, что разошлось
kumm files 3603               файлы мода: fileId, версия, дата, размер
kumm get 3603 --out mods      скачать главный файл
```

## Две половины

| | |
|---|---|
| `kumm.mjs` | ходит на Nexus: сверяет версии, качает файлы |
| `Deploy-ModPack.ps1` | раскатывает сборку по папкам игры и проверяет результат |

Обе работают **по манифесту** и своих данных не хранят. Сама сборка — манифест,
конфиги и библиотека архивов — живёт отдельно и в этот репозиторий не входит:
это личная коллекция, у неё свой git.

```powershell
# сборка лежит где угодно, движок знает о ней только через -PackDir
.\Deploy-ModPack.ps1 -Verify -PackDir "D:\Games\Palworld Mods"
.\Deploy-ModPack.ps1 -Deploy -PackDir "D:\Games\Palworld Mods" -Only UltraGraphics
```

Без `-PackDir` скрипт берёт манифест рядом с собой — так работает сборка,
которая носит движок внутри себя.

Игра задаётся манифестом: `nexusGame` для адресов Nexus и `gameExe` для проверки,
что папка назначения действительно установка этой игры (без ключа — Palworld).

## Зачем ещё один инструмент

Nexus не даёт API-загрузку бесплатным аккаунтам: эндпоинт `download_link`
только для премиума. Поэтому существующие CLI либо требуют премиум
([nexmod](https://github.com/morecitricacid-coder/nexmod)), либо честно
отправляют кликать руками
([nexus-collection-dl](https://github.com/scottmccarrison/nexus-collection-dl)),
либо кликают за тебя по картинке на экране
([NexusAutoDL](https://github.com/jaylann/NexusAutoDL)) — хрупко и требует
окна на переднем плане.

KUMM работает иначе. Ссылку на файл он получает тем же путём, что и сам сайт:

```
POST /Core/Libs/Common/Managers/Downloads?GenerateDownloadUrl
     fid=<file_id>&game_id=<window.current_game_id>
  → {"url": "https://files.nexus-cdn.com/… подписанная ссылка"}
```

Дальше файл тянет обычный `fetch`. Никакой эмуляции кликов, окно Chrome
остаётся в фоне, ошибки видно, имя файла формируется по той же схеме, что даёт
сам Nexus.

## Установка

```bash
git clone https://github.com/MikalaiKryvusha/kumm
node kumm/kumm.mjs launch
```

Или глобально: `npm i -g .` и дальше просто `kumm`.

Нужен установленный Chrome. Профиль для отладки заводится отдельный
(`%LOCALAPPDATA%\nexus-cdp\profile`) — начиная с Chrome 136 отладочный порт на
профиле по умолчанию игнорируется. В нём один раз логинишься на Nexus, дальше
куки живут в профиле.

```bash
kumm login      # откроется окно входа
kumm status     # проверить, что залогинен
```

## Манифест сборки

`check` и `update` сравнивают библиотеку архивов с Nexus. Им нужен
`modpack.json` в корне сборки:

```json
{
  "nexusGame": "palworld",
  "library": "mods",
  "mods": [
    { "name": "UltraGraphics", "nexusId": 3603, "version": "1.2.2" }
  ]
}
```

Архивы в библиотеке лежат под именами, которые даёт Nexus:

```
Ultra Graphics 1.2.2 3603 1.2.2 2026-08-03T15-13Z MZ9w71yK5.zip
                     ^id  ^версия ^дата загрузки
```

Отсюда KUMM и узнаёт, что у тебя стоит. Сравнение идёт **по дате загрузки
файла**, а не по строке версии: авторы перезаливают файл, не трогая номер, и
наоборот — в шапке мода версия одна, а у файла другая.

Библиотеку, собранную руками через сайт, KUMM тоже читает: кнопка Download
называет файлы по-другому — поля через дефис, в конце секунды Unix.

```
Better Sneak v3-1921-3-5-1747646868.zip
                 ^id  ^версия ^дата загрузки
```

Метка времени в этом имени — то же число, что сайт отдаёт на странице файлов,
поэтому сверка точная. Файлы без неё (`4gb_patch.zip`) движок не берёт: сравнивать
нечего.

Если на странице мода несколько разных файлов (не версий, а именно разных —
`ArmorSkills` x2 и x10, патч рядом с основным модом), какой из них твой, решает
маска `source.archive`; `nexusId` только сужает поиск.

Командам `files`, `get`, `changelog`, `eval` манифест не нужен — им хватит
`--game <slug>`.

## Мелочи, на которые напарываешься

- У мода бывает несколько главных файлов: Steam и Gamepass, Capped и обычный,
  разные пресеты. KUMM берёт тот, что ближе по имени к уже лежащему в
  библиотеке; выбрать явно — `--variant steam`.
- Метаданные файлов берутся из `dt[data-id][data-name][data-version][data-date]`,
  а не из текста карточки: свёрнутые секции аккордеона в `innerText` не попадают.
- Часть кнопок Nexus уехала в shadow DOM веб-компонентов — поиск в
  `page.locate` умеет туда проваливаться.
- В `kumm eval` на Windows не передавай JS с двойными кавычками: их съедает
  разбор аргументов. Внутри JS используй одинарные.

## Команды

| Команда | Что делает |
|---|---|
| `launch` | поднять Chrome с отладочным портом |
| `login` | открыть страницу входа |
| `status` | жив ли порт, под кем залогинены |
| `check [--json]` | сверить библиотеку с Nexus |
| `update [modId…]` | скачать всё, что разошлось, в `--out` (по умолчанию `mods/_incoming`) |
| `files <modId>` | список файлов мода |
| `get <modId> [fileId]` | скачать файл; без `fileId` — главный |
| `changelog <modId>` | changelog со страницы мода |
| `eval <url> <js>` | выполнить JS на странице |
| `close` | закрыть отладочный Chrome |

Флаги: `--game`, `--root`, `--manifest`, `--out`, `--variant`, `--port`,
`--profile`, `--settle`.

## Оговорки

Инструмент работает под твоим аккаунтом и повторяет ровно тот запрос, который
делает сам сайт при ручном скачивании. Он не обходит платные ограничения и не
раздаёт чужие файлы. Не гоняй его пачками без нужды — это чужой сервер, и
правила Nexus никто не отменял.

Разметку Nexus меняет регулярно. Если что-то отвалилось, начни с
`kumm eval <url> <js>` — разобраться, что там теперь в DOM.

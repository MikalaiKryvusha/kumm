## Что уже сделано и что известно

1. Новый лаунчер обновляет сборку по списку файлов выпуска. Он сверяет файлы прежней сборки со списком и скачивает только изменившиеся файлы. Между RC1 и
   RC2 по-настоящему изменились 12 файлов на 37,3 МБ, а обновление скачало 12,8 ГБ.
2. Для такого обновления на странице выпуска лежат файлы сборки по одному и список файлов. Для сборки размера RC2 это 73 файла: 70 файлов от 1 МБ,
   вторая часть самого большого пака (он больше 2 ГиБ) и один архив со 117 мелкими файлами.
3. Лаунчеры RC1 и RC2 уже у игроков. Они обновляют сборку только частями архива: сейчас это 7 частей, 13,7 ГБ. Свой лаунчер они обновляют отдельной
   кнопкой, когда игрок её нажмёт.
4. Первую установку новый лаунчер тоже ведёт частями архива. По одному списку файлов он обновляет только уже поставленную сборку (стенд 2026-11-21,
   кейс D4: выпуск без частей архива лаунчер честно называет на экране и сборку не ставит).
5. Ручная установка по руководству идёт частями архива: «Скачайте в одну папку все части архива сборки». <!-- ru-ok: quoted guide line -->
6. Выгрузка выпуска RC2 на GitHub шла около 37 минут (части собраны 2026-11-20 в 23:20, выпуск опубликован в 23:57). Части архива и файлы по одному
   вместе удваивают выгрузку.
7. Первое обновление после RC2 при любом ответе ещё раз скачает сторонние паки целиком (около 13,6 ГБ): RC2 упакован прежним способом. Со следующего
   выпуска скачивается только разница.

- **A) (рекомендую) И части архива, и файлы сборки по одному со списком файлов**
  - Ситуация. Следующий выпуск открывают трое: игрок с лаунчером RC2, игрок с новым лаунчером и новичок.
  - Действие. Первые двое нажимают «Обновить сборку», новичок скачивает лаунчер или части архива по руководству.
  - Результат. Лаунчер RC2 обновляет сборку частями архива, как сейчас. Новый лаунчер скачивает только изменившиеся файлы. Новичок ставит сборку частями архива, руководство остаётся прежним. На странице выпуска около 83 файлов, выгрузка выпуска идёт примерно вдвое дольше.
  - Проверка. `make_release.sh` выгружает части архива, файлы по одному и `manifest.json`; ритуал выпуска сверяет оба набора с GitHub. Так устроены выпуски у Velopack: в каждом выпуске полный пакет и разница (разведка `researches/conan-launcher-delta-update/README.md`, §5).
- **B) Только файлы сборки по одному со списком файлов**
  - Ситуация. Следующий выпуск открывают игрок с лаунчером RC2, игрок с новым лаунчером и новичок.
  - Действие. Игрок с лаунчером RC2 нажимает «Обновить сборку», новичок открывает руководство.
  - Результат. Лаунчер RC2 отвечает, что в выпуске нет полного архива сборки. Сборка обновится, только если игрок сначала нажмёт кнопку обновления лаунчера. Новичок поставит сборку, когда агент научит лаунчер первой установке по списку файлов, ручная установка из руководства уходит, для Nexus нужен отдельный архив. Выгрузка выпуска остаётся прежней.
  - Проверка. `make_release.sh` без шага частей архива; новая работа — первая установка по списку файлов (план 57, фаза 6, критерий 5) и новая глава руководства.
- **C) И то, и другое до выпуска 1.0.0, после него только файлы по одному**
  - Ситуация. Выпуски до 1.0.0 и после него.
  - Действие. Игроки обновляют сборку и ставят её впервые, как в вариантах A и B.
  - Результат. До 1.0.0 всё идёт, как в варианте A. После 1.0.0 всё идёт, как в варианте B: к тому времени лаунчер умеет первую установку по списку файлов, а игроки получили новый лаунчер.
  - Проверка. Два режима `make_release.sh`; первая установка по списку файлов готова до 1.0.0.

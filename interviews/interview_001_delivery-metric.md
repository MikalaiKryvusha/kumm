# Интервью #001 — метрика поставки и каденция молитвы (KAIF 2.5)

> Тема: две настройки владельца, которые привезло обновление KAIF 2.2 → 2.5 и которые агент не выбирает сам.
> Источник: обновление KAIF 2.5, задание `KAIF_UPDATE_TASK.md` → пункт `policy-changes`; чат 2026-09-05.
> Статус: **🟡 ждёт ответов владельца**

## Контекст — что уже известно

KAIF 2.5 требует, чтобы `MASTER_PLAN.md` называл **одну метрику поставки** — счётное расстояние до
приёмки владельцем. Эту метрику агент печатает строкой `DELIVERY: X → Y` при каждом закрытии сессии и в
каждой итерации автономных циклов; `/what-next` ранжирует задачи по ней первой; судья охотится на её
отсутствие. Остальные правила 2.3–2.5 (символ веры, `FORK:`, лестница тяжести S1/S2/S3, пара
`/end-chat-soft` · `/end-chat-force`) — решения самого автора фреймворка в origin, здесь они приняты как
есть и записаны в журнал решений `MASTER_PLAN.md`.

Факты, ограничивающие варианты:

- Фаза 1 мастер-плана — «движок, которому можно доверять без присмотра» — это **пять** конкретных
  автономных проверок (круговой ход `parseArchive` ↔ `libraryName` · кейсы `sameFile`/`stamp`/`pickCard` ·
  пакет фикстур для `check --json` / `-ListMods` / `-Deploy -DryRun` · дрейф упаковки `npm pack` ·
  настоящая команда `help`). Сегодня готово **0 из 5** — ни одного теста в проекте нет.
- Фаза 2 — вторая игра на одном манифесте. Сегодня **1 из 2**: Palworld живёт, манифест Oblivion
  Remastered на 168 модов исполняется движком, но игра не установлена.
- В origin KAIF вы уже сказали своё слово о форме метрики (issue #46, проект NDim Space): одно число
  скрывает разницу между «построено» и «связано», нужен **вектор** осей одного расстояния. Здесь оси
  две: «доверяем» и «построено».

## ВОПРОСЫ

### Q1. Какая метрика поставки стоит в `MASTER_PLAN.md`?

**Цель ответа:** `MASTER_PLAN.md` → строка «Delivery metric (one line)» (сейчас там предложение агента с
пометкой «ждёт слова владельца»).

**Происхождение:** обновление KAIF 2.5 ввело обязательную строку `DELIVERY:` и требует ОДНУ согласованную
с владельцем метрику; без неё каждый отчёт агента и каждая итерация цикла будут судиться как неполные.
Вопрос сформулировал агент 2026-09-05 при обновлении; ответ питает `MASTER_PLAN.md`, `STATUS.md`
(ранжирование беклога через `/what-next`) и все отчёты циклов.

- **A) (Рекомендовано)** Вектор из двух компонентов: `автономные проверки ядра: 0 из 5 · игры на одном
  манифесте: 1 из 2`. Ведущий компонент (в слот `X → Y`) — проверки, пока идёт фаза 1; когда фаза
  закроется, ведущим становится второй. Почему: это ваша же форма из issue #46, оба числа считаются
  сегодня командой (`node --test` / список фаз), и один скаляр здесь спрятал бы либо доверие, либо рост.
- **B)** Один скаляр — `автономные проверки ядра: 0 из 5`. Проще, но после фазы 1 метрику придётся менять
  вашим словом заново.
- **C)** Один скаляр — `игры на одном манифесте: 1 из 2`. Ближе к видению, но вся фаза 1 будет давать
  нулевую дельту «с названным блокером» — метрика молчит там, где идёт работа.
- **D) Свой вариант владельца** — например, число ручных шагов при обновлении сборки, если вы хотите
  считать именно свой труд.

### Q2. Каденция молитвы перед работой?

**Цель ответа:** `AGENT_GUIDE.md` → блок `KAIF:PRAYER`, клетки каденции в директиве.

**Происхождение:** в 2.5 каденция объявлена настройкой владельца; умолчание — полный текст (символ веры
+ 16 принципов) перед каждой нетривиальной задачей и при каждом освежении контекста. В проекте KAGO вы
выбрали иначе (интервью 017, Q2 = B, 2026-08-28): полный текст один раз за сессию, дальше — одна
строка с тремя принципами под задачу.

- **A) (Рекомендовано)** Полный текст один раз за сессию на входе (`/resume`), перед каждой следующей
  задачей — одна строка «символ веры и молитва произнесены в <время>» с тремя принципами, важными для
  этой задачи. Почему: ваш выбор в KAGO; меньше шума в чате, применение вместо декламации.
- **B)** Умолчание 2.5 — полный текст перед каждой нетривиальной задачей и при каждом освежении.
- **C)** Только символ веры перед каждой задачей; молитва — раз за сессию.
- **D) Свой вариант владельца.**

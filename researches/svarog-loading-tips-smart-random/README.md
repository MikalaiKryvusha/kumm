# Разведка — умный рандом советов экрана загрузки

> **Created:** 2026-10-17
> **Parent:** слово владельца `[OWNER]` «нужна система умного рандома, чтобы те советы, которые показывались - получали меньший шанс
> показаться из всех советов, а те, которые ещё не показывались - больший шанс - и чтобы оно между сессиями запоминалось» ·
> «разведка в сети. как такое делается»
> **Status:** разведка (код не писали; моделирование — скриптом в scratchpad, числа ниже — из его вывода)

## Как сейчас

Советы игры — массив `LoadingScreen.loadingTips` (61 строка в коде). Мод KrinikUIRework (`SvarogsDream/src/KrinikUIRework/LoadingTips.cs`)
дописывает в конец массива наши 35 строк из `krinik_loading_tips_ru.txt`. Выбирает игра: `ShowRandomTip()` берёт
`Random.Range(0, loadingTips.Length)` и пишет «Tip N: текст». Зовёт его `OnEnable()` и `Update()` раз в 10 с
(`KUMM/games/SvarogsDream/GAME_ARCHITECTURE_INTERNAL_MAP.md` §2). Памяти нет ни внутри сессии, ни между сессиями: один совет может
выпасть дважды подряд, а другой — не выпасть за сотни загрузок.

## 1. Как это решают на практике

| Приём | Суть | Где описан |
|---|---|---|
| Мешок (shuffle bag) | все элементы кладут в мешок, перемешивают, тянут без возврата; мешок пуст — наполняют заново | Jon Davis, Envato Tuts+, 2012: [shuffle bags](https://code.tutsplus.com/shuffle-bags-making-random-feel-more-random--gamedev-1249t) — «`Random()` isn't fun», генератор «doesn't care if it returns all 1s» |
| Мешок на 7 (Tetris) | семь фигур перемешиваются и выдаются пачкой; засуха фигуры I — не больше 12 подряд | [Tetris Wiki: Random Generator](https://tetris.wiki/Bag) |
| История с перебросом (TGM) | помнят 4 последние фигуры; выпала одна из них — бросают заново, до 4–6 раз | [Tetris Wiki: TGM randomizer](https://tetris.wiki/TGM_randomizer) |
| Мешок, который подкладывает давно не бывших (TGM3) | мешок на 35; каждый раз в мешок возвращают копию фигуры, которой не было дольше всех; ни одна фигура не пропадает дольше 35 ходов | [Tetris Wiki: TGM randomizer](https://tetris.wiki/TGM_randomizer) |
| Взвешенный выбор | сумма весов → бросок → идём по списку, вычитая веса; O(n) | [LootLocker: weighted random](https://lootlocker.com/blog/random-with-weights) |
| Штраф за показ хранить отдельно от веса | менять не сами веса, а множители к ним; иначе веса «сползают к минимуму» и ломаются при добавлении новых элементов | Unity Discussions, Bunny83: [weights less likely when picked](https://discussions.unity.com/t/random-weights-and-making-them-less-likely-to-be-chosen-when-picked-and-vice-versa/949915) |
| Перезарядка (cooldown) | недавно показанное не участвует в выборе N ходов | [DisOrder, список изменений](https://www.chiark.greenend.org.uk/ucgi/~mdw/git/disorder/blobdiff/cebe31278d4990696382196884fa42d897b15a3f..36a1a882e0852f29a63b4e7cfad5e465dfa14fde:/CHANGES) (недавно игранное не берётся в случайный выбор); [Godot Forum](https://forum.godotengine.org/t/how-to-randomize-instances-without-repeating-the-previous-one/8806) (исключить предыдущий) |
| Растущий шанс после промахов (pity) | шанс растёт на C с каждой неудачей и сбрасывается при срабатывании (PRD Warcraft III / Dota 2) | [Liquipedia: Random Distribution](https://liquipedia.net/dota2/Random_Distribution), [Diplograph](https://diplograph.net/notes/games/randomness/dota-2-prd) |

**Советы и «совет дня» — живые примеры:**
- PowerShell-модуль tiPS хранит список ID показанных советов; режим по умолчанию — все показаны, список очищается, круг заново;
  новые советы с новыми ID считаются непоказанными ([tiPS PR #153](https://github.com/deadlydog/PowerShell.tiPS/pull/153/files)).
- wxPython «Tip of the day» сохраняет номер текущего совета при выходе и продолжает с него; Microsoft Access — ID последнего
  показанного ([wxPython wiki](https://wiki.wxpython.org/action/raw/How%20to%20create%20a%20Tip%20of%20the%20day%20frame%20%28Phoenix%29?action=raw),
  [Microsoft: Startup Tips](https://learn.microsoft.com/en-us/previous-versions/office/developer/office-xp/aa140099(v=office.10))).
- Roblox DevForum: чистый `math.random` повторяет советы, лучше идти по кругу ([тред](https://devforum.roblox.com/t/screengui-changing-tips-solved/1836059)).
- Spotify в 2014 ушёл от честной перетасовки Фишера — Йетса: люди жаловались, что подряд звучат песни одного артиста
  ([Spotify Engineering, 2014](https://engineering.atspotify.com/2014/02/how-to-shuffle-songs) — сейчас отдаёт 404, содержание по
  [SlashGear](https://www.slashgear.com/1546972/how-to-fix-spotify-shuffle-feature/)).
- Сид Мейер, GDC 2010: случайность должна казаться игроку честной, иначе он считает, что компьютер жульничает
  ([Game Developer](https://www.gamedeveloper.com/pc/gdc-sid-meier-s-lessons-on-gamer-psychology)).

**Вывод.** Мешок — самый простой способ «без повторов», но у него два изъяна под наше слово: показанный совет получает не «меньший
шанс», а ноль до конца круга, и новый совет ждёт следующего круга. Слово владельца точнее всего ложится на взвешенный выбор со
счётчиком показов и перезарядкой — это мягкий мешок, как у TGM3.

## 2. Где хранить память между сессиями

| Вариант | Плюсы | Минусы |
|---|---|---|
| `PlayerPrefs` | одна строка кода | на Windows пишет в реестр `HKCU\Software\<компания>\<продукт>` вперемешку с настройками игры ([Unity 2020.3](https://docs.unity3d.com/2020.3/Documentation/ScriptReference/PlayerPrefs.html)); на диск — при `OnApplicationQuit()` или по `Save()` ([PlayerPrefs.Save](https://docs.unity3d.com/2020.3/Documentation/ScriptReference/PlayerPrefs.Save.html)): падение игры теряет память; не видно, не удалить руками |
| Свой файл в `BepInEx/config` | папка конфигов модов, `Paths.ConfigPath` ([BepInEx API](https://docs.bepinex.dev/api/BepInEx.Paths.html)); файл видно, сбросить — удалить файл | десяток строк кода чтения и записи |

Запись без порчи: сначала во временный файл, потом `File.Replace` (есть в .NET Framework 4.x,
[Microsoft Learn](https://learn.microsoft.com/en-us/dotnet/api/system.io.file.replace?view=netframework-4.8)); при первой записи
файла ещё нет — `File.Move`.

**Ключ совета — не номер.** Номер в массиве сдвинется, как только добавим или уберём совет. Ключ — хеш текста. Встроенный
`string.GetHashCode()` для этого не годится: Microsoft прямо пишет, что он меняется между версиями и платформами и его «should never be
persisted» ([String.GetHashCode](https://learn.microsoft.com/en-us/dotnet/api/system.string.gethashcode?view=netframework-4.8)).
Нужен свой хеш, например FNV-1a 32 бит по UTF-8 — пять строк кода
([Wikipedia: FNV](https://en.wikipedia.org/wiki/Fowler%E2%80%93Noll%E2%80%93Vo_hash_function)). Хешировать исходный текст: у
авторских — английскую строку из массива (XUnity переводит её позже, при показе), у наших — русскую строку файла. Правка текста
совета делает его «новым» — для исправленного совета это правильно.

## 3. Края

- **Новый совет** приходит со счётчиком 0, а у остальных счётчики выше — он почти наверняка выпадет в ближайшие загрузки.
- **Дважды подряд** не бывает: перезарядка K выключает последние K показанных.
- **Все показаны** — отдельного сброса нет: важна разница с минимумом, круг начинается сам.
- **Убранный совет** (выключен `ExtraTips` или автор удалил строку) — строку в файле не трогать: вернётся совет — вернётся и его
  счётчик.
- **Битый или чужой файл** — прочесть, что читается, остальное считать нулями; ни одного исключения наружу.
- **Цена** — один проход по ~96 советам на показ, раз в 10 с и только на экране загрузки; запись файла — там же, не в кадре
  геймплея (бюджет 1 мс на моды касается геймплея).

## 4. Рекомендация `[AI]`

**Мягкий мешок: вес по счётчику показов и перезарядка.**

1. Для каждого совета хранить `n` (сколько раз показан) и `last` (номер показа, когда показан в последний раз). Общий счётчик
   показов `tick` тоже хранить.
2. Вес совета: `w = 8^-(n − nmin)`, где `nmin` — наименьший `n` среди нынешних советов. Каждый лишний показ сверх самых редких делит
   шанс на 8. Показанный совет не выпадает из игры, но непоказанные выигрывают у него в 8 раз.
3. Перезарядка: если `tick − last ≤ K`, вес 0; `K = min(10, N/3)`. Все веса нулевые (крошечный список) — брать любой, кроме прошлого.
4. Бросок: сумма весов → `Random.value * сумма` → проход по списку. Затем `n++`, `last = tick`, `tick++`, запись файла.
5. Встроить префиксом на `LoadingScreen.ShowRandomTip`: выбрать номер и написать «Tip N: текст» тем же форматом, что игра, — XUnity и
   `NameOurTip` работают как прежде.

**Файл** `BepInEx/config/krinik_loading_tips_seen.tsv`, UTF-8 без BOM:

```
# tick	412
# хеш	n	last	начало текста (только для глаза)
9f3a01c2	5	407	(пример строки: первые слова совета)
```

**Что показало моделирование** (96 советов, 1000 показов, 300 прогонов; через 500 показов добавлены 5 новых советов; скрипт
`node SvarogsDream/tools/sim_tips.mjs`, перенесён из временной папки 2026-10-17; повторный прогон дал те же числа — `8^-d`: все 96 за 132 / 152):

| Способ | Все 96 увидены за (медиана / 95%) | Тот же совет дважды подряд | Повторы ближе 10 показов | 5 новых увидены за (медиана) |
|---|---|---|---|---|
| сейчас (`Random.Range`) | 497 / 774 | 3075 из 300 000 (~1%) | 9.9% | 207, а в 5% прогонов не все за 500 |
| мешок | 96 / 96 | 0 | 0.5% | 164 (ждут следующего круга) |
| `4^-d`, K=10 | 159 / 186 | 0 | 0 | 5 |
| **`8^-d`, K=10** | **130 / 152** | **0** | **0** | **5** |
| `16^-d`, K=10 | 115 / 128 | 0 | 0 | 5 |

Основание 8 — середина: ближе к мешку по охвату, но показанный совет ещё может выпасть, как и просил владелец («меньший шанс»).
Основание — одна константа в конфиге, крутить по вкусу.

**План проверки.**
1. Скрипт выше перенести в `SvarogsDream/tools/` и держать как тест выбора: 0 повторов ближе K, медиана разброса `max n − min n` ≤ 2 через 500
   показов, новые советы — за ≤ N/10 показов.
2. Команда отладки в моде: 10 000 холостых выборов по настоящему списку — гистограмма в журнал, без записи файла.
3. В игре: две сессии подряд — `tick` во второй продолжает первую; дописать пробный совет — он выпадает за первые загрузки; удалить
   файл — счёт с нуля, игра не падает.

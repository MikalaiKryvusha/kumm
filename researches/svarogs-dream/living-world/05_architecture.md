## 1. Суть в одном абзаце

Поверх игры живёт **книга жизни** (ledger): у каждого персонажа мира — запись в цифрах (где он, куда идёт, чем занят,
здоровье, кошелёк, фракция, распорядок). Книга тикает **раз в игровой час** (60 реальных секунд) и между тиками двигает
путников вдоль их пути. Персонажи рядом с героем — обычные объекты игры («онлайн»), их полностью ведёт сама игра. Ушёл
персонаж за 300 м — мод **усыпляет** объект игры и переводит персонажа на запись («офлайн»). Подошёл герой — объект
**просыпается там, где его поставила книга**, с её здоровьем, кошельком и занятием. Так устроены A-Life S.T.A.L.K.E.R. и
«галактика» «Космических рейнджеров» (файлы 01–02 этой папки); у нас это ложится на уже работающий сон дальних
(`SvarogsDream` `89a0629`).

## 1а. Ступени и пять правил (теория — `02_theory.md`)

| Ступень | Где | Чей | Что считается |
|---|---|---|---|
| **L0 Во плоти** | 3 × 3 участка игры | игра | настоящий объект; запись книги «выдана» и заморожена |
| **L1 Преддверие** | кольцо вокруг (5 × 5 без 3 × 3) | книга | точное место на дороге; готов войти в зону **у её края** («прибытие», а не «раскрытие» — Chenney) |
| **L2 Мир** | всё остальное | книга | узел/ребро графа, дела по времени, стычки, торговля |
| **L3 Совокупность** | поселения | книга | безымянный счёт (стража, крестьяне, товар); личность рождается при встрече с героем (Watch Dogs: Legion) |

Пять правил:
1. **Ровно один хозяин** у персонажа в каждый миг — игра или книга; выдача и возврат — явные, с полным снимком; **перед
   сохранением игры** все выданные возвращаются в книгу — сохранение согласовано само с собой.
2. **Состояние — с метками времени и формулой** (дело: начало–конец; ребро: время выхода, скорость): «где он в момент t»
   считается, а не хранится пошагово.
3. **Считать только наблюдаемое** — кто где, жив ли, что несёт, кто чем владеет; у каждой стычки — **след** (тела,
   добыча, время, срок исчезновения), чтобы пришедший позже герой нашёл подтверждение исхода.
4. **Открытые системы с пределами темпа** — краны и стоки, лимиты в час, наблюдатели инвариантов (всё золото, товар,
   население фракций) в журнале.
5. **Бюджет и гистерезис** — мс на кадр, материализация из пула вразбивку, кольца с запасом, флаг «важный» у виденных
   героем (их не чистить и не перегенерировать — «раннее алиби», Sunshine-Hill).

Детерминизм: случайность — хеш-функция от (семя мира, ID персонажа, номер события), например Squirrel3 (GDC 2017 «Math for
Game Programmers: Noise»); игровое время — целым числом; никаких `UnityEngine.Random` и `deltaTime` внутри книги. Стычки —
**предсказываются**, а не ищутся опросом: входя на ребро, группа считает момент встречи с враждебными группами на нём и
ставит событие «встреча»; если встреча выпадает на L0/L1 — обе стороны материализуются, и бой идёт по-настоящему.

## 4. Запись персонажа

```csharp
// Книга жизни: одна запись на персонажа мира. Только данные — никаких ссылок на объекты Unity, кроме кэша.
// [NOT-TESTED] эскиз
enum NpcTask : byte { Routine, Travel, Trade, Fight, Flee, Dead }

sealed class NpcRecord
{
    public string Id;                 // PersonalID игры (или путь объекта, если ID нет)
    public Vector3 Pos;               // где он сейчас (офлайн — по книге)
    public int HomeTile;              // участок, к которому привязан (столбец * 1000 + строка)
    public Fractions Faction;         // фракция игры
    public float Health01;            // доля здоровья 0..1 — переносится в CharacterStats при пробуждении
    public int Purse;                 // монеты (для торговли и добычи)
    public int LootValue;             // ценность несомой добычи (сумма, без предметов — предметы рождаются при продаже)
    public NpcTask Task;
    public Vector3 Goal;              // текущая цель (место слота распорядка, рынок, лагерь врага)
    public Vector3[] Path; public int PathIndex;   // путь по карте путей игры, считается один раз на смену цели
    public float SpeedMps;            // метры в секунду (у игры ходьба = speed / 2, PhysicSetter.cs:79-141)
    public RoutineSlot[] Routine;     // 24 слота — снимок таблицы AIDailyRoutine при первом знакомстве
    public bool Online;               // объект игры сейчас активен и ведёт себя сам
    public int Seed;                  // своё семя случайности (Рейнджеры): решения повторяются при повторе сохранения
    public int HoursSinceSeen;        // часов, как герой его не видел (Рейнджеры, Starsector) — ключ ко всем «подтасовкам»
    public int GroupId;               // решает группа (путники, отряд, стая), одиночка — группа из одного (A-Life, AlifePlus)
    [NonSerialized] public GameObject Go;          // кэш объекта (может быть null, если участок не загружен)
}

struct RoutineSlot { public Vector3 Place; public byte Action; }   // пустой слот — Place = (NaN)
```

## 5. Такт книги

```csharp
// Решения — по игровому часу, но не всем сразу: «долг тиков» по кругу (Bannerlord) в бюджет кадра (AlifePlus: 0.1 мс в
// среднем, предел 2 мс). Положение вдали — по формуле, а не пошагово (разведка 03): где путник сейчас = откуда + доля
// ребра грубого графа по времени. Онлайн-записи пропускаются: их ведёт игра.
// [NOT-TESTED] эскиз
const double BudgetMs = 2.0;
double _tickDebt; int _cursor;

void Update()                                        // один ведущий Update мода
{
    _tickDebt += Time.deltaTime / GameHourSeconds * _groups.Count;   // каждая группа — раз в игровой час
    var sw = Stopwatch.StartNew();
    while (_tickDebt >= 1 && sw.Elapsed.TotalMilliseconds < BudgetMs)
    {
        var g = _groups[_cursor = (_cursor + 1) % _groups.Count];
        _tickDebt -= 1;
        if (g.Online || g.Dead) continue;
        if (g.HoursSinceThink >= g.ThinkEveryHours || g.EventFired) Decide(g);   // пересмотр раз в 3–6 ч или по событию
        g.HoursSinceThink++; g.HoursSinceSeen++;
    }
}

// Где группа на ребре графа прямо сейчас — без пошагового движения; догонялка после перемотки времени бесплатна.
Vector3 PosNow(Group g, double gameHourNow)
{
    var e = g.Edge;                                   // от узла A к узлу B, длина L метров
    double t = Math.Min(1.0, (gameHourNow - g.DepartHour) * g.SpeedMph / e.Length);
    return Vector3.Lerp(e.A.Pos, e.B.Pos, (float)t);  // t = 1 — пришёл: событие «прибытие» → Decide
}
```

Цена: несколько сотен–тысяч групп × простая арифметика в бюджет 2 мс на кадр; потоки, Jobs и видеокарта не нужны — Jobs
без Burst в Mono медленнее простого C#, Burst игре 2020.3 недоступен (`03_mods_unity.md`).

## 6. Переход онлайн ⇄ офлайн (на готовом сне дальних)

```csharp
// В PatchCharacterDraw.Sleep / WakeTick (мод камеры) — два вызова книги. [NOT-TESTED] эскиз
static void Sleep(CharacterStats cs)
{
    var r = Ledger.GetOrCreate(cs);                  // первое знакомство: снимок распорядка, фракции, кошелька
    r.Pos = cs.transform.position;
    r.Health01 = (float)cs.currentHealth / Mathf.Max(1, cs.GetMaxHealth());
    r.Online = false;
    _asleep.Add(cs.gameObject);
    cs.gameObject.SetActive(false);
}

static void Wake(GameObject go)
{
    var r = Ledger.Of(go);
    if (r != null)
    {
        if (r.Task == NpcTask.Dead) { Ledger.CommitDeath(r); return; }  // умер офлайн — не будим; в список погибших игры
        go.transform.position = SnapToNavMesh(r.Pos);                   // где его поставила книга
        Ledger.ApplyHealth(go, r.Health01);
        r.Online = true;
    }
    go.SetActive(true);                              // игра сама запустит действие слота (OnEnable → ExecuteDailyAction)
}
```

Правила перехода (разведки 01–03):
1. Пробуждение **не происходит в кадре**: только за пределами экрана или на расстоянии, где фигура меньше нескольких точек;
   не больше одного персонажа в кадр (AlifePlus, Kenshi VSE).
2. **Буфер между линиями:** просыпается ближе 295 м, засыпает дальше 300 м **и** не виден героем N часов (Starsector:
   30 дней и 4 св. года; X-Ray: `switch·(1 ± factor)`) — без мигания на границе.
3. Ставить на карту путей (`NavMesh.SamplePosition`), иначе — в воздухе или в стене.
4. Умерший офлайн не просыпается и попадает в список погибших игры (иначе «воскреснет» после загрузки); у записи —
   «надгробие», чтобы её не поставили второй раз.
5. Счётчик **`HoursSinceSeen`** у каждой записи управляет всеми «подтасовками» (догонялка, перенос застрявших, события) —
   они происходят только там, где герой давно не был (Рейнджеры: события лишь в системах, где игрока не было 30+ дней).

## 7а. Голова записи — полезность, личность, стек целей (приёмы Unliminium, `04_unliminium.md`)

```csharp
// Решение путника вдали: из допустимых действий и «рекламы» умных объектов (рынок, логово, трактир, лагерь фракции)
// выбирается лучшее по полезности. Личность — веса в файле данных, а не код. [NOT-TESTED] эскиз
interface IAdvert { Vector3 Where { get; } Need Satisfies { get; } float Amount { get; } }   // «умный объект»

static float Score(NpcRecord r, IAdvert a, Personality p)
{
    // кривые отклика: каждая ось → 0..1; произведение = вето любой нулевой оси (IAUS)
    float need    = Curve.Logistic(r.NeedOf(a.Satisfies), k: 8f, x0: 0.5f);
    float dist    = Curve.Inverse(Vector3.Distance(r.Pos, a.Where) / 1000f);   // дальше — хуже
    float danger  = 1f - Curve.Linear(Danger.On(r, a.Where));                  // опасный путь — хуже
    float health  = Curve.Power(r.Health01, 2f);                               // раненый не идёт на охоту
    float s = need * dist * danger * health;
    s = Compensate(s, axes: 4);                                                // поправка на число осей (IAUS)
    return s * p.WeightOf(a.Satisfies);                                        // личность: жадный, осторожный, …
}

static float Compensate(float s, int axes)
{
    float mod = 1f - 1f / axes;
    return s + (1f - s) * mod * s;                                             // произведение многих осей не тонет
}
```

Стек целей (`researches/37` Unliminium): **стратегия** (2–5 условий по порядку отказа: разбогатеть, выжить, долг фракции)
→ **тактика** (одна промежуточная цель «чтобы …»: продать добычу в Баре) → **операция** (переход, бой, торг — с «готово,
когда» и аварийным порогом: здоровье ниже ¼ → бегство в ближайшее поселение). Перепланирование — по событию (засада,
задание выполнено, война), не каждый тик. Каждое решение пишет в журнал вклад осей — ответ на «почему он так сделал».

## 8. Стычка офлайн — исход броском

```csharp
// Сила стороны = Σ (уровень × доля здоровья × урон оружия); исход — по отношению сил с кубиком.
// Модель ланчестерского типа (разведка 03): сильная сторона теряет мало, слабая — много. [NOT-TESTED] эскиз
static void Fight(List<NpcRecord> a, List<NpcRecord> b, System.Random rng)
{
    double pa = a.Sum(Power), pb = b.Sum(Power);
    bool aWins = rng.NextDouble() < pa * pa / (pa * pa + pb * pb);     // квадрат — эффект численности (Ланчестер)
    var (win, lose) = aWins ? (a, b) : (b, a);
    double ratio = Math.Min(1.0, (aWins ? pb / pa : pa / pb));
    foreach (var r in lose) { r.Task = NpcTask.Dead; r.Health01 = 0f; }
    foreach (var r in win)
    {
        r.Health01 = Mathf.Clamp01(r.Health01 - (float)(ratio * 0.6 * rng.NextDouble()));
        r.LootValue += lose.Sum(x => x.Purse + x.LootValue) / Math.Max(1, win.Count);   // добыча делится
    }
    Log($"ledger fight {Names(a)} vs {Names(b)} → {(aWins ? "A" : "B")} p={pa:0}/{pb:0}");
}
```

Внутри стычки — повадки по образцу автомата Unliminium (`tools/engine/abm.mjs`): у каждого участника список приоритетов
«первое подходящее правило» (лечиться ниже ½, бежать ниже ¼, если вожак жив — не бежать; иначе бить цель по правилу
повадки: меньше всего здоровья / сильнейший удар), жребий при равенстве, «двойник» ≈10 % — повадка другого на один ход.
Поражение чаще оборачивается бегством с потерей добычи, чем смертью (урок Radiant AI — мир не вымирает за неделю).

## 9. Фракционный режиссёр (как «Warfare» A-Life)

Раз в игровой день: у каждой фракции — счёт территорий (участки, где её записей больше, чем чужих), «агрессия» растёт с
силой и падает с потерями; агрессивная фракция отправляет отряд из 3–6 записей к соседнему чужому участку. Встреча
отрядов на участке — стычка §8; победа — участок переходит. Рядом с героем отряд становится обычными персонажами игры, и
бой идёт по-настоящему (у игры для этого есть свои битвы фракций — `FactionWarBattleController`).

## 10. Сохранение

Книга — **отдельный файл рядом со слотом сохранения**, никогда не внутри сохранения игры (урок ButterLib: мод снят —
игра грузится). Пишется внутри сохранения игры (постфикс): временный файл → переименование; в файле — версия схемы,
игровое время и отпечаток сохранения (слот + время сохранения), при загрузке сверяются — старый сейв не подхватит чужую
книгу. Загрузка в две фазы (AlifePlus): прочитать при загрузке, применить, когда мир собран. Только ID (`PersonalID`),
никаких ссылок на объекты. Нет файла или он сломан — книга собирается заново из сцены (все 6 227 персонажей там есть), мир
не ломается. `JsonUtility` словарей не умеет — свой маленький сериализатор.

## 11. Проверка каждой ступени (сцена «ушёл — подождал — вернулся»)

- Ситуация: герой у деревни, в журнале `ledger hour …` видно N офлайн-записей.
- Действие: герой уходит дальше 300 м и ждёт 3 игровых часа (пульт: `call WorldTime IncreaseTimeByOneHour true` × 3).
- Результат: при возвращении жители стоят у мест своих слотов; у путников — изменились кошельки; при стычках — есть
  погибшие, и они не воскресают после перезагрузки сохранения.
- Проверка: строки журнала `ledger …` до/после, кадры `shot`, перезагрузка сохранения и повтор счёта.

## 12. Риски (Мёрфи)

- **(а) высокие:** порча сохранения (книга не совпала с игрой) — защита: книга вне файла сохранения игры, пересборка из
  сцены; конфликт с заданиями (умер нужный для задания) — исключения как у сна (бессмертные, `AIQuestLocations`,
  `QuestTarget`); рывок при пробуждении многих сразу — не больше 20 за такт (уже есть).
- **(б) средние:** экономика уходит в разнос (инфляция, пустые лавки) — у каждого источника денег и товара должен быть
  свой сток, в сумме они уравновешены (разведка 03); вымирание мира без возрождения — источник новых путников в
  поселениях.
- **(в) низкие:** путь через непроходимое (берём путь игры); перемотка времени (сон героя, быстрое перемещение) —
  книга догоняет пропущенные часы несколькими тиками подряд.

## Правила (своими словами, с цитатой источника)

1. **Любое изменение элемента пересобирает весь холст.** «Whenever any drawable UI element on a given Canvas changes, the Canvas
   must re-run the batch building process»; изменение — это и положение, и масштаб. Отсюда: не писать в трансформ значения, которые
   не меняют картинку; одинаковое значение не будит рассылку (проверено у нас: `testcases/TC_svarog_billboards_2026-10-10.md`), а
   сброс-и-возврат — будит.
2. **Делить холсты по частоте изменений.** Статичное — на одном холсте, меняющееся — на своих мелких. У игры у каждого значка свой
   холст в мире — изменение одного не трогает соседей. Это правильно для подвижных значков, ломать не надо.
3. **Прятать — выключением компонента Canvas.** «merely enable/disable the Canvas component»: сетка сохраняется, при включении нет
   пересборки, не идут OnEnable/OnDisable по дереву. Альфа 0 — плохо: «the element will still be sent to the GPU». SetActive у корня
   — сбрасывает сетку, при включении полная пересборка.
4. **Выключенный холст не выключает скрипты.** «this will not disable any MonoBehaviours within the hidden UI» — их Update идёт
   дальше. Дорогие покадровые компоненты прячущегося значка выключать отдельно.
5. **Лучи интерфейса.** GraphicRaycaster перебирает все картинки своего холста с Raycast Target каждый кадр; холстам без кликов
   GraphicRaycaster не нужен, а картинкам без кликов — Raycast Target. Холсты в мире без заданной камеры ищут `Camera.main`
   («If this property is not set, then Unity UI will search for the main camera»).
6. **Сотни Update — дорого сами по себе.** Каждый Update — переход из движка в C#; один менеджер, который проходит массив, дешевле
   сотен Update (форумный замер: 1000 объектов × 10 компонентов — 0.3–0.4 мс менеджером против 4.4–5.2 мс обычными Update).
   Для ~200 значков выигрыш меньше, но и цена переделки мала: у значка игры в Update только поворот к камере.
7. **Отсекать невидимое и дальнее.** Плашки над юнитами показывать только для тех, кто в кадре и рядом (форумы — общая практика; у нас
   дальность 100 м уже есть, 2026-10-05).
8. **Экранный холст вместо холстов в мире** — частый совет для плашек (проекция `WorldToScreenPoint` + один экранный холст), но
   форумный замер показал примерно ту же цену, а один большой холст пересобирается целиком при сдвиге любой плашки. Для нас — нет:
   значки игры уже на своих холстах, переносить их — переписывать поведение игры без выигрыша.

## Что из этого сделано в службе значков (2026-10-10)

| Правило | В коде (`Icons.cs`) |
|---|---|
| 1 | размер и место считаются без сброса (точки значка подобны относительно опоры); запись — только при разнице больше полуточки 4K; камера стоит — ни одной записи |
| 3 | дальше радиуса — `Canvas.enabled = false` (как и раньше); альфа — только в полосе угасания 5 м, CanvasGroup заводится по нужде |
| 4, 6 | Update значков игры (поворот к камере) выключен; поворот, дальность, размер и место — один проход службы за кадр |
| 5 | GraphicRaycaster на холсте значка выключается (щелчок по значку идёт лучом в хозяина — `IconClick.cs`) |
| 7 | вне кадра (одна точка хозяина, запас ¼ экрана) — значок не трогается |
| — | проход — в `Canvas.preWillRenderCanvases`: после LateUpdate камеры, до сборки холстов — без отставания на кадр |

## Почему этого не было сразу (разбор ошибки)

Служба росла по репликам владельца («крупнее», «выше», «левее», «до 100 м») слой за слоем, и каждый слой проверялся глазом на
виде — цену самого механизма никто не прикидывал до глубокого профиля 2026-10-10. Руководство Unity по интерфейсу до кода не
открывалось. Урок — EXPERIENCE (покадровый код без прикидки цены и без правил движка).

## 0. Key facts first

- **The central dispatcher is `UISugestionManager`** (one "g"; file `UISugestionManager.cs`), reached as `WorldState.Instance.worldStateInjector.suggestionManager` (`WorldStateInjector.cs:44`). It holds two child systems: `public UIInfoMessages uiInfoMessages;` (`UISugestionManager.cs:10`) and `public UICharacterMessages uiCharacterMessages;` (`UISugestionManager.cs:12`).
- **`UIInfoMessages` is one spawn point for about a dozen message kinds.** Almost every method does `Object.Instantiate(<prefab>, base.gameObject.transform)` (`GameUI/UIInfoMessages.cs:451,456,461,466,471,484,493,499,517,521,527,537,542,561-579`). Each message is a new child of the same transform, so several can be on screen at once. Code never destroys them, except the town banner (`Object.Destroy(..., 20f)`, `GameUI/UIInfoMessages.cs:499-510`). Lifetime and layout (LayoutGroup or overlap) come from the prefabs and are **not determinable from code**. `Instantiate(original, parent)` keeps the prefab's local RectTransform, so every one of these messages is placed relative to the `UIInfoMessages` object. **Moving that object moves all of them.**
- **`UICharacterMessages` holds pre-placed singleton widgets**: 11 `UISkillUp` level-up toasts, an item-picked toast, a random-skill toast and a new-day banner (`GameUI/UICharacterMessages.cs:7-35`). A new call **re-uses and resets the same widget** (no queue, no stacking). Example: `ShowItemPicked` resets text, fills and timers (`GameUI/UISkillUp.cs:34-51`), so rapid pickups overwrite each other.
- **Cast errors such as "Not enough mana." are not a toast system.** They are a second cast bar, `CastBarNoMana`, whose `customText` shows the message (`SpellActivator.cs:11`, `ActionBarUI/UICastBar.cs:37,322-325`).
- **Many short messages ("Inventory full.", "Door is locked.") are world-space, not HUD.** They go through `UIPopUpSpawner.ShowText` (97 call sites), which spawns a world-space `TextMeshPro` that billboards to the camera and floats up (`GameUI/UIPopUpSpawner.cs:309-317`, `GameUI/UIPopUpText.cs:13-23`). By the task's boundary that is out of scope, but it is listed in section 3 because it carries most "error" texts.
- **No code positions any of these channels.** No message class sets `anchoredPosition`, `anchorMin` or `anchorMax`. The only positional code is the generic `UISlideUp` / `UISlideIn` helpers (offset 500 units, `GameUI/UISlideUp.cs:7,16`; `GameUI/UISlideIn.cs:7,16`), and code never says which prefabs carry them. **Whether any channel overlaps the bottom hotbar is unknown from code for every row.**
- **"AlwaysVisibleBars" does not exist in code.** No class, field or string by that name. The only near match is `WorldState.isAlwaysVisibleWapon` (`WorldState.cs:17`), a weapon-visibility flag. "AlwaysVisibleBars" must be a GameObject name inside a prefab or scene.
- **Time-scale coupling.** `UISkillUp`, `UIRandomSkill` and `UIGodsFavor` run on `Time.deltaTime` (`GameUI/UISkillUp.cs:74,83,99,102`; `GameUI/UIRandomSkill.cs:45-46,55`; `GameUI/UIGodsFavor.cs:33,36`). The cast bar and fade helpers wait with scaled `WaitForSeconds` (`ActionBarUI/UICastBar.cs:298`; `GameUI/UIFadeAway.cs:36`). Tips and world events set `Time.timeScale = 0.1` (`TipsManager.cs:309`, `WorldEventsManager.cs:1909,1941` → `UtilMethods.cs:215-217`) or `0` (`UtilMethods.cs:206-208`). While a tip or event is open, these toasts last up to 10 times longer in real time, or freeze completely.

## 2. Which channels share one UI object (moving one moves the others)

1. **`UIInfoMessages` transform (one object).** It is the parent of every instantiated message: #3 custom, #4 custom+icon, #5 quest started, #6 quest finished, #7 level-up, #8 recipe discovered, #9 save/save-failed, #10 load-failed, #11 save-file deletion/restart, #12 chapter titles, #13 town entered (`GameUI/UIInfoMessages.cs:451-579`, all `Instantiate(..., base.gameObject.transform)`). The singleton shout objects of #14 are fields of the same component (`:79-161`); whether they are its children is unknown from code. **Moving or re-anchoring `UIInfoMessages` moves all of #3–#13 together.** #13 and #3 can fire in the same trigger (`TownEnteredMessage.cs:18,28`).
2. **`UICharacterMessages` (one object, separate child widgets).** #15 (11 widgets), #16 `itemPickedMessage` (same `UISkillUp` class and visuals as #15), #17 `randomSkill`, #18 `newDayMessage` (`GameUI/UICharacterMessages.cs:7-35`). Whether these widgets sit in one layout under that object is prefab data.
3. **`UICastBar` class, two instances.** #1 `CastBar` and #2 `CastBarNoMana` are separate serialized fields (`SpellActivator.cs:7-11`). Code does not say whether they overlap or share a parent. `CastSpell` has its own serialized `CastBar` field (`CastSpell.cs:10`), presumably wired to the same bar as #1, but code cannot confirm it.
4. **Same visual class, different objects**: #19 and #20 duplicate the reveal code and share `UIFadeAway`. #21 uses one `UIGodsFavor` script on many objects that share the global `isGodsFavorPopupActive` gate.
5. **Side-effect sharing**: #3, #5 and #7 also toggle the same badge objects, `InfoPanelMarkedIcon` / `InfoPanelMarkedQuestTab` and `characterPanelMarkedIcon` (`UISugestionManager.cs:6-20,30-31,66-67,83-84,103-105`).

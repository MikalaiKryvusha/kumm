## 1. Official workflow (GUI)
- Docs (https://exiles-enhanced.inflexion.io/modding/): "Copy mod into `_InstalledPath_/UE4/Content/Mods` folder → Launch the devkit → Select your mod (auto-selected if only one exists) → Hit Play In Editor." DDC: "Zen stores its cached data in your user `AppData` folder", relocatable per Epic docs. Redirectors in engine INIs relink moved assets. Sub-pages: art, building, creatures, http, regions, ui, uploading, uniqueid-refactor.
- Editor UI strings **[LOCAL]** `UE4/Plugins/DreamworldMods/Binaries/Win64/UnrealEditor-DWModDevKit.dll`: buttons/actions "Choose Assets For Cook", "Build mod", "Debug: Only cook mod", "Upload built mod to {0}"; output message "Successfully built mod to '%s'". Mod window appears under editor Window menu as "Conan Exiles DevKit" only when launched with `-ModDevKit` (https://github.com/jvdberg1/exileforge).
- What "Build mod" actually runs (UAT via RunUAT, strings in the same DLL **[LOCAL]**):
  - `-NoCompile BuildMod -Mod="%s" -Project="%s" -Cook -ScriptDir="%s"`
  - `-NoCompile BuildMod -Mod="%s" -Project="%s" -Pak -Compress -ScriptDir="%s"` (or `-Pak` without compress)
  - `BuildMod -Mod="%s" -Project="%s" -FinalPak -ScriptDir="%s"`
- Paths **[LOCAL]** `BuildMod.cs`: sources `UE4/Content/Mods/<Mod>/` (new assets under `Local/`, overrides under `Content/`, shared under `Shared/<Mod>/`); asset list `UE4/Content/Mods/<Mod>/Local/CookInfo.ini` (`[/CookInfo]` + `FilesToCook=` lines, "make sure one has been generated in editor with 'Choose Assets For Cook'"); cook temp `UE4/Saved/Mods/_Cooked/[Platform]/`; staged `UE4/Saved/Mods/<Mod>/Staged/`; final `UE4/Saved/Mods/<Mod>/Output/<Mod>.pak` (override with `-Output=`). Active mod = empty `active.txt` in the mod folder (`SetActiveMod` command).
- Output layout (comment in `BuildMod.cs` **[LOCAL]**): outer uncompressed `<Mod>.pak` mounted at `{ProjectRoot}/Mods`, containing `modinfo.json`, `manifest.json` (MD5 + nested `"<xxh128>"` XXH128 hashes), and per platform `<Mod>-Windows|WindowsServer|LinuxServer.{pak,utoc,ucas}`; the inner `.pak` holds `AssetRegistry.bin` and `ModCompat.bin`, the `.utoc/.ucas` hold the cooked packages and renamed `ShaderArchive-<Mod>-*` bytecode. Compression: Oodle Kraken level 7 / Optimal3.
- Disk: Epic Store item is 145.15 GB download / 165.9 GB installed, first added 5 May 2026, last build 2 Jul 2026 (https://egdata.app/items/981d3f375ed449c38237d88893a0bb4a/changelog); exileforge says "~160 GB". First-launch time: **NOT FOUND** for Enhanced; legacy-kit reports only ("loading times can be quite long the first times", ShaderCompileWorker stuck at 72% — https://forums.funcom.com/t/conan-exiles-dev-kit-won-t-launch-because-of-shadercompileworker-exe/175175). Community cook time: "about 8 minutes" for a 3-table mod (exileforge).
- Upload (https://exiles-enhanced.inflexion.io/modding/uploading/): "use the Upload button on the mod kit window"; first upload creates a Workshop item; legacy ID kept in `modinfo.json` but unused, new ID stored in `steamWorkshopFileIds`; uploader auto-tags `Enhanced`.

## 2. Headless / command-line cooking
- Canonical (exileforge, verified by its author on `5.6.1-366792 (++exiles+release)`; identical to what the GUI runs per §1):
  ```
  "<DevKit>\Engine\Build\BatchFiles\RunUAT.bat" -NoCompile BuildMod -Mod=<ModName> -Project="<DevKit>/UE4/ConanSandbox.uproject" -Cook -Pak -Compress -ScriptDir="<DevKit>/UE4/"
  ```
  "Include `-ScriptDir=<DevKit>/UE4/`. Omit it and UAT reports `Failed to find command BuildMod`" (https://github.com/jvdberg1/exileforge). `-Project` defaults to `ConanSandbox` if omitted; `-Mod=` is mandatory **[LOCAL]** `ModDevKitCommand.cs`. Kit README explains why `-ScriptDir` is needed: the automation "should potentially live in Plugins/DreamworldMods … shenanigans to get that showing up in the AutomationTool" (https://epicprosupport.epicgames.com/s/question/0D5QP000002xLyt0AE/… cited in **[LOCAL]** `UE4/Build/ModDevKit.Automation/README.md`).
- What BuildMod does internally **[LOCAL]** `BuildMod.cs`: sets `UE_SKIP_UBT_SDK_SETUP=1` (so LinuxServer cook works without the Linux cross-toolchain), then runs the `Cook` commandlet via `UnrealEditor-Cmd` with `-OutputDir=… -ModDevKit -NoAssetRegistryCache -TargetPlatform=Windows+WindowsServer+LinuxServer -NoGameAlwaysCook -NoDefaultMaps -SkipSoftReferences -SkipHardReferences -SkipZenStore -ini:Game:[/Script/UnrealEd.ProjectPackagingSettings]:bGenerateNoChunks=True -PackagesList=…` (versioned cook, no `-unversioned`), then `UnrealPak.exe` three times per platform (loose pak with `-CreateMultiple`, iostore with `-CreateDLCContainer="" -CookedDirectory -Commands -WriteBackMetadataToAssetRegistry=Disabled` plus `-PackageStoreManifest/-ScriptObjects` or `-ProjectStore`), then a final uncompressed wrapper pak. Note "UnrealPak in 5.8 won't overwrite, so we need to delete an existing file first".
- Headless DataTable editing (exileforge): `"<DevKit>\Engine\Binaries\Win64\UnrealEditor-Cmd.exe" "<DevKit>\UE4\ConanSandbox.uproject" -run=pythonscript -script="ef_editor.py" -unattended -nopause -nosplash -stdout`, using `unreal.DataTableFunctionLibrary.export_data_table_to_csv_file / fill_data_table_from_csv_string`, `unreal.EditorAssetLibrary.duplicate_asset / save_asset` (https://raw.githubusercontent.com/jvdberg1/exileforge/main/tools/ef_editor.py). Bundled interpreter: `Engine\Binaries\ThirdParty\Python3\Win64\python.exe`.
- The 2026 breakage "Found no script module records": reported only by **daveCode-dot/aegis-ue5-modkit** — "RunUAT BuildMod … fails with 'Found no script module records' — UAT scans for a ScriptModules manifest and deletes its own deps.json as 'invalid record' before BuildMod can run"; "ships in installed-build mode … standard RunUAT BuildPlugin is blocked"; its workaround = "Python + Unreal Editor Remote Exec + UnrealPak bypass" (search snippet, https://github.com/daveCode-dot/aegis-ue5-modkit). **The repo returns 404 on github.com, raw and the API as of today** (the author's profile lists only `unreal-ai-connection`), so the scripts could not be read. Generic UE cause/fix for the same error: missing `<Project>/Build/Scripts/*.Automation.csproj`, or `-NoCompile` without a matching editor exe — fixed by `-NoCompile -UnrealExe=UnrealEditor-Win64-DebugGame-Cmd.exe` in one case (https://forums.unrealengine.com/t/packaging-for-win64-not-working-uathelper-packaging-windows-error-system-exception-found-no-script-module-records-ue5-0/522447). In this kit the record exists at `UE4/Intermediate/ScriptModules/ModDevKit.Automation.json` (`TargetPath: uatbin\Development\ModDevKit.Automation.dll`) **[LOCAL]** — a sound `-ScriptDir=<DevKit>/UE4/` should find it; if UAT rejects it as stale, the aegis description suggests it is the deps.json/record validation, not the DLL.

## 3. Dev kit version vs game version
- Kit is `release-beta` CL 374980; live game `release` CL 373655 (task context). The kit is built to be ahead of live: DWModDevKit strings **[LOCAL]** "A new game release is coming soon{0}. Uploading mods to the live product is disabled until {1}", "…Uploading mods to the live workshop remains enabled, so mods should be tested against the live game before uploading", "Cannot upload the mod to steam now as it is incompatible with the game on retail. Try using the Public Beta Client workshop instead.", "Unknown target steam workshop %d, disallowing upload." (`ReleaseComingSoonUploadsEnabled` flag).
- Runtime compatibility check (`UnrealEditor-DreamworldMods.dll` **[LOCAL]**): BuildMod writes `ModCompat.bin` ("schema-compatibility manifest … MountMod reads it before loading"; "%d class record(s), %d override path(s), %d custom version(s) (cooked against engine %s)"). Game messages: "Mod is too new and incompatible for this game version", "Mod '%s' schema check found %d potential data-loss issue(s)", "Incompatible Mods Detected", "You are running incompatible mods with this version of the game. The following mods failed mounting:", plus `ServerModMismatchList`. `modinfo.json` carries `MinimumVersion:"Enhanced"`, `DevkitRevisionNumber`, `DevkitSnapshotID`. So: a mod cooked on a NEWER kit (custom-version/package-version ahead of live) is refused as "too new"; an OLDER cook is accepted and only schema-checked (data-loss warnings). Exact match is not required, "not newer" is.
- Funcom's cadence: every 2026 devkit entry says "This is a major update, most mods will need a re-cook" (Mar 31, Jul 7, Jul 28 2026; asset-change txt files attached) (https://forums.funcom.com/t/mod-devkit-patch-notes/199863). Patch notes: "Mods can be brought over from UE4/Legacy, and will require upgrading, recooking, and repackaging for UE5/Enhanced" (https://forums.funcom.com/t/conan-exiles-enhanced-patch-notes/296991). Server-hoster view: "UE4-compiled mod paks don't load in a UE5 game binary"; "Don't rename mod pak files" (https://low.ms/blog/conan-exiles-enhanced-mods-what-works-now). Level-cap authors report re-fixes after game patches ("save-loading crashes discovered after game patches", https://steamcommunity.com/sharedfiles/filedetails/?l=english&id=3735146411).
- **NOT FOUND**: any forum thread describing the specific symptom of a beta-kit cook on live; the Steam "Mod mismatch"/"mod wrong version" threads are age-gated and unreadable here (https://steamcommunity.com/app/440900/discussions/0/3397427506573277453/, https://steamcommunity.com/app/440900/discussions/0/3159763879054508044/).

## 4. DataTables: ModController vs overlay override
- Official (legacy, still valid per docs): ModController = "a central hub for your mod where you can attach your new snazzy data-tables to core game data-tables"; create Blueprint Class → parent "Modcontroller" inside the mod folder; `ModDataTableOperations` runs at startup; "PreLoad" subfolder with its own ModController for pre-main-menu data (https://www.conanexiles.com/wp-content/wiki/2685370865.html). Nodes: `Merge Data Tables` (same row struct; existing rows overwritten, new added), `Merge Data Tables With Control Table` (struct `Data Table Merge Control Row`: `MergeControl_Default`, `ColumnsToOverride`, `ColumnsWithRowsToInsert`, `ColumnsWithRowsToRemove`; example on `DT_MonsterXP` merging only `Difficulty` by default and `Difficulty+XP` for `Alpha_Elephant`), `Remove Data Table Rows`, `Clear Data Table` (https://www.conanexiles.com/wp-content/wiki/2491842561.html). Steam guide walkthrough incl. "Build Mod" and "Built Mod Folder" buttons (https://steamcommunity.com/sharedfiles/filedetails/?id=2158109909).
- Enhanced level-cap mods edit `DT_AttributeSystem`, `DT_ExperienceSystemLevel`, `DT_FeatsPerLevel` (MrSerji's Level 1000, https://www.nexusmods.com/conanexilesenhanced/mods/15; Why Stop At 60 "custom XP table 61–120", "place at the BOTTOM of your load order", installs to `…\Conan Exiles\ConanSandbox\Mods`, https://www.nexusmods.com/conanexilesenhanced/mods/7). Neither page says whether they use ModController or full-table replacement.
- Overlay override (no Blueprint): author the table at `/Game/Mods/<Mod>/Content/Systems/Progression/DT_ExperienceSystemLevel`; the cooker strips `Mods/<Mod>/Content/` so it "becomes `/Game/Systems/Progression/DT_ExperienceSystemLevel` and replaces the base table" (exileforge; confirmed by `FileToPackage` remap in **[LOCAL]** `BuildMod.cs`). exileforge gotcha: `LogModController: Invalid class` → "drop the ModController; use overlay override instead". Trade-off: whole-table replace is incompatible with other mods touching the same table (Nexus pages warn exactly that).
- **NOT FOUND**: Enhanced-specific official docs on ModController/merging (the inflexion.io site has none; it points to the UE4 docs).

## 7. Gotchas
- Long paths: "short install path such as `C:\ConanDevKit`", "Long paths break cooks" (exileforge). ExitCode 28 / "Unable to find package for cooking" = assets outside `Mods/<Mod>/Content/` or bad `CookInfo.ini` paths; "empty mod folder after headless edits" = asset-registry desync (exileforge).
- `ProtectedAssets.pak`: **NOT FOUND** in any source (no Funcom/Inflexion/forum mention); only "Localization.pak" and "Don't rename mod pak files — renamed paks silently fail to load on Enhanced" (https://low.ms/blog/conan-exiles-enhanced-mods-what-works-now).
- Server variants: BuildMod always cooks `Windows, WindowsServer, LinuxServer` and packs all three into the wrapper; "the game extracts, verifies, and mounts the set of paks for the current platform at runtime" **[LOCAL]** `BuildMod.cs`. Server-side: `ConanSandbox/Mods/modlist.txt`, one `*<name>.pak` per line, `ServerModList=modlist.txt` in `Saved/Config/LinuxServer/ServerSettings.ini`; client mods at `steamapps\common\Conan Exiles\ConanSandbox\Mods` or Workshop `steamapps\workshop\content\440900` (https://xrealm.com/en/blog/conan-exiles-enhanced-how-to-add-mods, https://www.nexusmods.com/conanexilesenhanced/mods/15). Load order must match client/server (exileforge).
- Local-only cook vs Workshop: nothing forces upload; "Upload built mod" is a separate step; "only uploading modinfo" mode exists ("This will just update the mod info… The actual mod won't be uploaded!") **[LOCAL]** DWModDevKit strings. Upload can be blocked before a game release (§3). Font/UI assets legitimately vanish from *Server cooks (`ClassesExcludedOnDedicatedServer`) — BuildMod only fails if a package is missing on all platforms **[LOCAL]**.
- Docs stale: inflexion.io says 5.6.1, kit is 5.8.2 **[LOCAL]**; StableId migration (`UUniqueID`→`FStableId`, deprecation warnings 2.2, removal ≥2.3) affects Blueprint mods (https://exiles-enhanced.inflexion.io/modding/uniqueid-refactor/).
